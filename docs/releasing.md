# Выпуск приложения для скачивания

Публичные сборки находятся в [GitHub Releases](https://github.com/Melnk/semestr/releases). Ссылка в README всегда ведёт на файлы последнего релиза с постоянными именами:

- `Semestr-macOS-universal.dmg` — установка через перенос приложения в «Программы».
- `Semestr-macOS-universal.zip` — архив того же приложения.
- `SHA256SUMS.txt` — контрольные суммы обоих файлов.

## Локальная сборка

На Mac с Xcode Command Line Tools, Node.js 22.13+ и pnpm 11.25.0:

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm desktop:release
SEMESTR_TEST_OUTPUT="$PWD/artifacts" dist/Семестр.app/Contents/MacOS/Semestr --ui-test
```

Скрипт компилирует `arm64` и `x86_64`, объединяет их в один Mach-O, запускает проверки базы, добавляет лицензии библиотек, создаёт иконку и ad-hoc подпись. Затем упаковывает DMG/ZIP и проверяет образ. Результат — `dist/release/`. Локальная база пользователя в пакет не входит.

Релизы пока не подписаны Developer ID и не заверены Apple. Без сертификата и учётной записи Apple это ограничение нельзя устранить одной настройкой упаковки. Инструкция первого запуска включена в DMG и README. Скрипты не меняют защитные настройки macOS.

## Опубликовать следующую версию

1. Обновить `package.json` и значения версии/номера сборки в `scripts/build-macos.sh`.
2. Добавить описание в `docs/releases/vX.Y.Z.md`, проверить изменения и дождаться зелёного `Checks`.
3. Создать и отправить тег `vX.Y.Z`, указывающий на проверенный коммит.
4. В GitHub Actions открыть **Publish macOS release → Run workflow** и указать тег.

Workflow собирает приложение из этого тега, прогоняет проверки, сверяет версии и публикует файлы. Существующий релиз не перезаписывается. Для первой публикации те же проверенные файлы могут быть загружены через `gh release create` с `--verify-tag` и `--notes-file`.

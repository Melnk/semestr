# Обновления приложения Mac

С версии 0.5 в «Настройках» есть текущая версия, переключатель ежедневной проверки и кнопка «Проверить обновление». Та же команда доступна в меню «Семестр». При обнаружении новой версии в основном окне появляется плашка с кнопкой «Обновить».

Проверка включена по умолчанию: при запуске, возвращении в приложение, пробуждении Mac и затем по таймеру, если с последней успешной проверки прошло 24 часа. Неудачная попытка повторяется не чаще раза в час. Пока приложение закрыто, проверки не выполняются; при следующем открытии просроченная проверка запускается. Ручная команда работает и с отключённой автоматической проверкой. При ошибке известная новая версия остаётся доступной, сообщение об ошибке видно в настройках.

«Обновить» скачивает DMG и контрольные суммы выбранного релиза, проверяет размер и SHA-256, затем открывает файл через macOS. Повторное нажатие открывает уже скачанный файл после повторной проверки. Повреждённый файл не открывается. Загрузка сама по себе не закрывает приложение, не заменяет `.app` и не изменяет учебную базу. Закройте «Семестр», перенесите новую версию с заменой в папку, где держите приложение, и запустите её. В версиях до 0.5 механизма проверки нет: первую новую сборку нужно скачать с GitHub.

Параметр проверки, дата последней попытки/успешной проверки и сведения о релизе записываются в `~/Library/Application Support/Semestr/updates.json`. Это настройка конкретного Mac, она не входит в перенос учебного профиля. Загруженные установщики находятся в `~/Library/Caches/Semestr/Updates/`. Приложение можно обновить и через обычную ссылку [GitHub Releases](https://github.com/Melnk/semestr/releases).

## Сеть и проверка файлов

Нативный код обращается к [публичному GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) для `Melnk/semestr`. Запрос не содержит учебных записей, имени, настроек, токена или идентификатора аккаунта; GitHub получает обычные данные соединения, включая IP. Используется отдельная эфемерная URLSession без cookies и сохранённых учётных данных. UI и шрифты остаются локальными.

Принимаются только опубликованные стабильные релизы с версией `vMAJOR.MINOR.PATCH`, готовым `Semestr-macOS-universal.dmg` и `SHA256SUMS.txt`. Числовое сравнение исключает предложение старой или той же версии. URL файлов должны точно соответствовать репозиторию, тегу и ожидаемым именам. Переадресации допускаются только по HTTPS на GitHub и его домены загрузки релизов. Размеры и время запросов ограничены; приложение не исполняет текст релиза, команды или пути из ответа API.

Контрольная сумма защищает от повреждения загрузки; она не является независимой цифровой подписью издателя. Установщик получает метку quarantine, проверки macOS сохраняются. Релизы пока ad-hoc подписаны, без Developer ID и нотариализации Apple.

## Проверки

`--update-self-test` использует управляемое время и тестовый транспорт: числовые версии, ежедневная проверка, перезапуск, отключение, ручной запрос, сбой сети и восстановление, параллельные запросы, откат часов, неполный/предварительный релиз, адреса файлов, повреждённая загрузка, quarantine и повторное открытие. В `--ui-test` проходят настоящие React/WKWebView и нативный мост с тестовым источником релиза; настоящий установщик не открывается, пользовательские данные не читаются.

`--update-check` проверяет публичный GitHub настоящим транспортом во временном каталоге. `--update-download-check` дополнительно скачивает и проверяет настоящий DMG, подменяя только открытие установщика; временные файлы удаляются. Эти проверки требуют сети и запускаются отдельно от воспроизводимых тестов сборки. Замена приложения пользователем и системные диалоги macOS остаются ручными действиями.

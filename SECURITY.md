# Безопасность

Для локальной версии Mac приоритетны сохранность SQLite, проверка импортируемых связей и ограничение нативного моста. Данные не отправляются на сервер. База не зашифрована самим приложением: используйте защиту учётной записи и диска macOS.

Для отдельной серверной версии приоритетны исправления изоляции данных, аутентификации, импорта и зависимостей. Это первая версия, внешнего аудита пока не было.

Не публикуйте уязвимость вместе с рабочими токенами или чужими данными. При размещении репозитория включите Private vulnerability reporting в GitHub Security → Advisories и используйте **Report a vulnerability**. Если такой канал ещё не настроен, свяжитесь с владельцем развёртывания через указанный им приватный контакт. Не выдумывайте адрес для сообщений и не отправляйте описание в публичный issue до согласования.

В приватном отчёте укажите версию/commit, минимальное воспроизведение на вымышленных аккаунтах, влияние и возможное исправление. Сроки ответа определяет поддерживающий репозиторий; гарантированного SLA нет.

На публичном сервере обязательны HTTPS, `SECURE_COOKIE=true`, точный `APP_ORIGIN`, собственный пароль PostgreSQL, закрытые порты БД/SMTP, резервные копии и регулярные обновления зависимостей. Не включайте SQL/body/debug-логирование паролей, cookies и email-токенов. Настройка — в `docs/self-hosting.md`.
